# WineFox: Skyfarer

> 酒狐会种田、会做饭、会施法、会打架
> 所以会飞，应该也很合理吧？

**WineFox: Skyfarer** 是一个为 **Touhou Little Maid** 制作的 NeoForge 附属模组，为女仆新增工作模式 **「骑空士」**。

装备好 **鞘翅、长矛和推进装备（雨中/水中的激流三叉戟或烟花）** 后，女仆将不再满足于站在地上和怪物互殴。

她会：

- 使用鞘翅与安全激流/烟花自主起飞
- 搜索并选择适合攻击的目标
- 从空中建立攻击航线
- 高速俯冲并使用长矛发动攻击
- 命中后立即脱离，而不是贴着目标刮痧
- 拉升、重新调整航向，然后开始下一轮攻击
- 在没有敌人后返回主人附近并降落
- 追着天上的幻翼打……至少我们的目标是这样

简单来说：

**给酒狐一根长矛和几发烟花，然后获得一架需要喂蛋糕的生物战斗机。**

如果你想问为什么酒狐连这个都会：

建议不要深究。

## 配置项详解

### 物理预测与路线储备（0.6.1）

飞控预测已按当前开发环境的 **Minecraft 1.21.1 / NeoForge 21.1.250 mapped 源码**核对：重力、俯冲/拉升耦合、float 查表、速度归零、阻力、烟花推进与 tick 顺序均进入预测。新生成火箭下 tick 才开始推进，活动火箭继续使用真实剩余寿命；背包有烟花不会被当成已经点燃。

能量数值用于比较路线和提前补能。进攻承诺必须通过完整 **Approach → Strike → Exit** 动力学认证，包括真实接触、身体通道、离场和火箭燃尽后的滑翔；高处不再因脚下谷底很深而得到虚假的能量信用。储备取全程最差值，正值不能覆盖预测失败。

实际 gravity（含 noGravity）与缓降效果在主线程冻结到 PhysicsContext；实体/Level/维度改变或释放重入时重新采集，获取失败使用 vanilla 默认值。后台只运行纯数学，不读取世界，也不为每只女仆创建线程池。长矛伤害、身体扫掠与 ATTACK_EXIT 的既有有界离场规则保持。

新增 `verifyVanillaPhysics`（18,000 步独立源码 oracle 差分）与 `verifyAttackEnvelope`（上下攻击、悬崖、完整出口及物理否决）；`build` 共执行 24 项离线验证。公式、生命周期、测试和适用边界见 [物理技术文档](docs/VANILLA_PHYSICS.md) 与 [验证说明](docs/VALIDATION.md)。未启动 Minecraft；第三方物理 Mixin、真实效果/火箭时序、跨维度重入及实际服务器性能仍需游戏内确认。

### 异步飞行规划（0.6.0）

飞控采用 **主线程快照 → 共享后台规划 → 有界结果邮箱 → 主线程验证与执行**。后台负责滑翔预测、烟花完整寿命评估、坡面采样分析、直线/俯冲/曲线候选生成与评分、连续追击及离场规划。现有原版鞘翅物理、真实物品消耗、长矛伤害与状态机仍由服务端主线程执行。

- `MaidTerrainSource` 只在主线程读取已加载且可更新实体的区块，将碰撞形状复制为不可变数值包围盒；不把 `Level`、`Entity`、`BlockState`、`VoxelShape` 或读取世界的回调交给后台。空区段直接生成空快照，不逐方块扫描。雪层、半砖等仍使用真实形状。
- 全服共用 2～4 个后台线程，控制预测与几何搜索分队列，合计最多 64 个排队任务；每只女仆最多 24 个待处理任务。满队列直接退让，不在主线程执行重计算，也不等待 `Future.get/join`。任务在碰撞查询点响应取消，卸载、任务释放及关服会清理任务与快照。
- 快照按需增量采集。每 tick 全服最多检查 256 个空间单元、读取 21,600 个方块，并在累计采集时间达到约 2 ms 后停止继续采集；时间预算在单元之间检查，单个单元可造成少量超出。这是**快照采集预算**，并非整个 Mod 的总 tick 时间保证。多女仆轮转分配，控制与候选预取都保留采集机会。
- 每只女仆最多缓存 768 个 `4×4×4` 单元，包含突出形状所需的一格边缘；20 ticks 后分批刷新，80 ticks 后过期。缺失快照按未知处理，不当空气执行。后台另有只用于请求数据的探索预测，优先预取候选通道及其边缘，探索结果本身不能执行。
- 结果带 generation，目标身份、逻辑阶段、配置版本或维度改变会取消旧任务。应用前还检查请求参数、结果年龄、当前位置、航向、速度和目标状态。普通控制结果最多复用 4 ticks；控制预测会滚动刷新，坡面分析可复用 20 ticks。
- 候选曲线几何可短暂保留，避免每一帧移动都毁掉此前可用的进场线；真正接入前另用当前状态验证身体通道、命中与离场。必要时重新验证离场高度或已有烟花补能策略，不能把旧几何直接当成当前可执行轨迹。等待进场候选时平缓转向；等待离场规划时立即停止沿用俯冲姿态。
- 曲线接入使用更严格的年龄、位置、航向、俯仰和速度校验；“已掠过目标”还需结合曲线进度，防止弧线起点位于目标末端切线平面另一侧时，刚开始攻击就提前离场。
- 主线程保留短距离真实身体扫掠、最终攻击射线、实际加载范围、着陆点和库存检查。这些用于防止新方块、区块卸载或外力使旧预测失效；不在主线程重新运行整套候选搜索。

创造赶路（包括 100 倍速）当前 tick 实际位移的实时扫掠仍在主线程，其极端速度下的耗时也需要实机测量。

调试 HUD 的“异步规划”行显示等待状态、generation、缓存单元、待采集单元、任务数及全服累计指标。`captureMs` 是累计主线程快照采集时间，`workerMs` 是后台累计计算时间；`stale` 计入取消失效的任务，`failed` 为后台异常数。`debuglog` 默认仍为关闭。黄色预测通道读取后台已有轨迹，绘制调试线不会另跑一遍规划器。

离线验证新增 `verifyAsyncPlanning`（线程/快照边界、取消、过期结果、队列与重启）、`verifyAsyncSweep`（完整快照与冷快照的候选几何）、`verifyPlannerLoad`（24 个会话的预算与公平性）。原有控制器、复杂地形和召唤回放现在通过真实线程池运行，使用 50 ms 的离线 tick 间隔；不会启动 Minecraft。负载报告写入 `build/reports/async-planner-load.txt`，其数值来自合成世界，不能代替实际服务器的 MSPT 测量。

### 复杂地形持续转弯攻击（0.5.4）

进场会同时评估直线、左右弧线和持续转弯切入的候选，不要求进场、目标和离场共线。新路线用两段三次 Bezier 曲线表示：起始切线来自当前三维速度，接触附近枚举不同方向、高度和身体侧向偏置，接触点与离场段共用位置和切线（C1 连续）。身体可以擦过目标旁边，由真实长矛射程完成接触，无需将女仆身体中心送入怪物脚下的台阶。

候选同时接受身体扫掠和原版鞘翅物理回放检查，必须能预计命中，并在有限火箭推进结束后继续安全离场。评分比较接触时间、净空、转向幅度和当前转向趋势，直线只保留少量简单性优势；原有竖向俯冲/坡面路线仍参与动态预测比较。不会仅因直线在几何上畅通就否决曲线，也不强制使用曲线。新路径只改变姿态指令，正常战斗不直接改写速度。

首次自动索敌仍要求可见，避免寻找地下洞穴目标；已经锁定的目标在进场中可以暂时被山体遮挡。曲线只查询已加载、可更新实体范围内的真实碰撞形状；最终接触仍检查攻击视线并由 Spears 执行实际伤害，不穿墙刺击。目标大幅移动、路线被新方块挡住或动力不足以安全继续时，会重新进入恢复/选路。

命中后优先沿已验证曲线离场，保留充能尾段；有安全的二段目标时仍可进入原有连续追击。接近目标之前保持曲线切向动量，只在最终长矛接触附近做瞄准修正，避免过早直指目标而切进山体。

调试棒新增**青绿色拟合攻击曲线**，覆盖进场、接触和离场；黄色通道继续表示按当前姿态、速度与火箭状态预测的实际身体体积，两者用途不同。HUD 原因行显示 `DIRECT`、`LEFT_ARC` / `RIGHT_ARC` 或 `LEFT_SWEEP` / `RIGHT_SWEEP`。原绿色入口方块和多女仆调试保持。

一次候选搜索完成后间隔 12 ticks 再开始新搜索；异步等待期间逐 tick 领取结果或补充缺失快照，不把这些重试视为新的进场机会。范围为目标附近 64 格，每个动力条件最多 216 个候选；无动力路线不可行时，可按真实可用库存生成拟点火候选，随后仍需全寿命重验与实际点火。后台碰撞快照与本 tick 实际控制的实时检查隔离。曲线跟踪及近段安全检查逐 tick 更新，火箭仍按库存、冷却和完整随机寿命范围验证。

### 骑空士指挥镜

`winefox_skyfarer:command_spyglass`（骑空士指挥镜）和 `winefox_skyfarer:creative_command_spyglass`（创造骑空士指挥镜）位于工具创造物品栏，暂不提供合成配方。

- **左键切换标记，右键保持原版望远镜缩放**，开镜与不开镜均可标记。标记准星沿线、方块未遮挡的活体目标，包含友好生物；玩家和所有女仆除外。两种镜都在服务端选取时排除 EntityMaid，与主人、工作和敌友无关。调试棒、女仆遥控器及远程调试仍可操作女仆。
- 每位玩家共享一个最多 5 个目标的列表，第 6 个挤掉最早的标记。再次左键同一目标取消；编号随列表顺序更新，不决定女仆的攻击顺序。
- 同 owner 的远程 Home/Follow 骑空士分批唤醒：每 10 ticks 最多 2 只，全服最多 8 个待唤醒任务；失败会释放票据并冷却重试，不永久跳过其余候选。任务结束回 Home 后，新任务会重新建立唤醒机会。`/wfs debuglog on` 的 `REMOTE_WAKE` 可逐 UUID 追踪发现、尝试次数、generation、加载、资格、接单与释放。
- 生存镜呼叫自己的跟随模式骑空士，以及距离玩家默认 128 格内的 Home 骑空士。创造镜需要玩家处于创造模式，默认可呼叫同维度、距离玩家 1000 格以内的自有骑空士（跟随与 Home 都受此限制）；`creative_command_range=0` 恢复无限距离。需要骑空士工作模式及鞘翅、长矛、战斗用烟花；坐下、睡眠、骑乘、拴绳或正在操作 GUI 的女仆不接受调度。
- 生存镜赶路保留 48 格交接距离。创造赶路默认 2 倍速度，最高 100 倍，尽量沿直线在 Y=200 附近巡航；短途、目标高度和维度顶棚会调整高度。水平距离 64 格开始直接下降，三维距离 32 格内移除免费推进、限制交接速度并交给正常战斗 AI。赶路不消耗背包烟花；创造倍率仅作用于赶路速度，不改变正常战斗物理、伤害或补能消耗。移动前检查整个身体扫掠通道，遇到障碍或尚未准备好更新实体的区块会减速或退回局部避障，不跳过碰撞检查。
- 标记目标是最高战略层级，其次为上一目标/主人或 Home 保护范围，再次为其他目标。同层保留幻翼优先、路线择优和失败换目标。每只女仆仍独立考虑位置、航向及上一目标，不按标记编号强制集中攻击。新标记在已承诺的攻击结束后重新评估；远程赶路中的目标保持固定，抵达后恢复常规选择，不必先落地再接新指令。
- 创造远程调度临时加载并更新当前区块和短距离前方通道，释放已经离开的票据。取消任务、死亡、退出、换维度和服务器关闭都会清理；重启不恢复旧指令或旧票据。生存镜仅短暂唤醒候选女仆，不维持远程飞行区块加载。
- 创造调度期间，只要仍有存活、仍被创造镜标记、且实际已加载的目标，Home 女仆落地也不会被工作区域逻辑提前传回家；被外部传送回远处后会重新进入赶路。有效创造目标全部消失时，空中继续安全返航，落地后使用 TLM 安全传送 API 回 Home，临时维持当前位置和 Home 区块直到回收成功或重试结束，避免先卸载女仆而丢失回收机会。
- 标记框、头顶 `▼` 与编号仅标记者可见，遮挡时只显示 `▼`。生存镜为亮红色，创造镜为亮紫色；新增标记时框从外向内收缩约 0.35 秒，标记成功和取消均播放原版音效。
- 调试棒可同时绑定多位女仆。右键女仆切换绑定；右键空气打开远程管理面板。默认方向键 ← / → 切换左上角 HUD（可在按键设置中修改）；所有绑定女仆继续显示各自红色目标线、蓝色航线和黄色碰撞预测通道。当前选中女仆显示亮绿色透视四角框，线宽为目标标记的三倍。
- 女仆卸载后保留本次连接中的最后快照，名字后以金黄色标注“（已卸载）”；重新加载后自动恢复实时数据。跨维度仍能切换 HUD，世界内线条只绘制当前维度。主动取消绑定或退出服务器会清除对应缓存，不用调试绑定强制加载实体。
- 远程面板列出女仆名称、完整 UUID、坐标、维度、距离和绑定复选框，跨维度距离显示 `(None)`；未加载女仆使用最后记录的位置。支持玩家下拉选择和名称搜索、分页，以及“玩家 → 女仆”“女仆 → 玩家”传送。沿用所有者权限：普通玩家管理自己的女仆，OP 2 可管理其他玩家。传送支持跨维度，最多等待 100 ticks 唤醒记录所在区块，完成、失败、玩家退出时释放临时票据；不改变女仆原有 Home 工作区域。
- 已通过走廊检查的攻击入口以一格绿色线框方块显示，中心引出两格长的进场方向线；与控制器实际采用的坡面、俯冲或普通进场方案同步，不绘制尚未被选定的假入口。

## 已知限制

动画效果、实际命中率、复杂地形与多人网络仍需要更多实测。短期预测不等同于完整三维寻路；完全封闭水域会释放控制回到女仆原有游泳流程。YSM 2.6.5 使用模型已有的滑翔动画和鞘翅挂点，缺失动画或其他 YSM 版本保留身体倾斜回退。遥控器只访问同维度已加载实体，不强制加载区块。带爆炸效果的烟花保留原版效果。
