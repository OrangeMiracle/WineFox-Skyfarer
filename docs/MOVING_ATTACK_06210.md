# 0.6.2.10 移动目标拦截与有界准备区

本次以本地 0.6.2.9 工作区为基线，保留上一轮未提交的续航和 Home 修复。没有恢复远程文件、引入 Funnel 或降低碰撞安全余量。

## 证据与根因

测试实例 debug.log 确认加载 0.6.2.9。latest.log 有反复 `sweep pending/selected=false`、APPROACH/REPOSITION 和补能循环；23:01:27–29 同一目标的距离由 49.905 增至 80.583、83.377 格。[摘录](../tools/moving-target-evidence.txt)。旧日志没有目标类型、运动向量或逐候选拒因，因此不能单凭这些行证明哪一个 UUID 是矿车中的骷髅，亦不能将所有失败归为同一原因。

源码与修改前回放确认：

- Sweep 以当前位置生成几何，但对 `aim + velocity × tick` 做接触测试，横移目标的候选终点和认证目标不一致。
- 低速移动与静止目标在几何缓存中可被视作兼容，静止曲线会延迟新的拦截搜索。曲线提案还要等待一次 Worker Rejoin，实体在等待中继续转向，接触窗口可能消失。
- AIR_RECOVERY 在攻击搜索之前运行，目标是当前动量方向前方 40 格、上方 4 格；紧凑重定位的范围中心又跟随当前女仆位置。
- 普通能量管理中的激流先于“保留可用低速入口”保护执行；等待攻击候选时可能抢占副手前摇，即使飞行能量足以完成当前入口。

## 当前实现

`SweepingAttackPlanner.interceptTicks` 根据目标水平速度、女仆速度和相对位置解 rendezvous 时间，并计入原生长矛前摇。移动目标使用预计时间的 1 / 0.65 / 1.35 倍生成三组未来 Strike Point；预测上限分别为 60 / 72 ticks，防止远期线性外推无限增长。每组仍含既有左右曲线、±50/60/70° 上升/俯冲，共最多 **648** 条候选；静止目标保留 216 条。每条均用 Vanilla 动力学、完整身体扫掠、原生 Spears 接触段、最小速度/前摇与 Strike→Exit 认证，不以“对齐好看”代替物理可达性。

运动仍从相邻 tick 的真实位置差采集，能观察乘客随矿车移动，即使乘客自身 velocity 为零。临近接触时，tracking 曲线用最新运动量更新短期拦截方向与长矛俯仰；停下/改向不会突然切回旧几何终点。超过 3 格/tick 的异常位移仍清零，不臆造矿车周期或预知下一次反向。

移动候选失败后每 3 ticks 重试（静止仍为 12）；失败的移动几何缓存只保留 3 ticks，并释放旧 seed。静止/移动提案不再相互兼容。已完成的几何仍只是提案：服务端对**一个选中路径**用当前姿态、当前目标速度和 ≤20 tick 已捕获 cells 重新模拟完整 Strike→Exit；成功才 commit。失败再交给有界 Worker Rejoin 搜索出口抬高/库存火箭，返回后仍须当前状态重验。静止曲线保留原 Worker Rejoin 入口；Worker 接触缓存的 2 tick/2.5 格/8°/速度 L1 0.35 门槛保持不变。主线程不做候选搜索，不查询新世界数据来同步补洞；缺数据排队采集并拒绝。新点火仍遍历该 Flight 的全部随机寿命，active rocket 保留剩余寿命。

准备区中心改为预计拦截点，运动提前量最多偏离目标 12 格；紧凑转向半径固定 48 格，不随每次向外飞的位置重新外扩。补能远时朝内、近时使用目标附近切向点，高度以攻击区高度为参照。该限制是局部计划约束，不是强制瞬移/硬削速度，也不保证任意障碍场景的真实航迹永不越过某一半径。

已有 Strike→Exit 证书优先于普通补能。初始最多 8 tick 的候选等待中，在水平速度 ≥0.65 且离地 ≥4 时保留长矛使用机会；不足仍允许能量处理，紧急碰撞防线始终运行。激流与烟花共同遵守保留已有入口的规则；真正低能量仍可空中恢复。

还修复了 Exit 重算的预算失配：完整攻击预测会在接触时延长离场时域，但单独 follow Exit 曾只给 24 ticks，安全的慢速曲线因此被误判失败。现在按剩余离场长度补足预算，仍上限 160 ticks、逐步扫掠；纯数值测试和两侧镜像山地命中→离场→落地回放共同覆盖。

## 诊断

`ATTACK_SEARCH` 通常每女仆 20 ticks 至多一条，commit 单独记录。包含目标 UUID、距离、实测运动、预计接触提前量、前摇、重试数、推进来源、候选数以及 geometry / noContact / exit / accepted / miss、Rejoin 拒因与异步队列状态。

- geometry：几何走廊不通过（含快照缺失或边界）。
- noContact：未获得认证接触，可能在接触前碰撞或在时限内未命中；不能只解释为射程不足。
- exit：预测已接触，但完整离场不通过。
- Rejoin：区分尚无 Worker 提案、缺失快照、当前接触失败、当前离场失败和已通过认证。
- `ATTACK_CONTINUATION_REJECT`：执行中的 motion、distance、miss、traceTicks、实际起点和 tracking 状态。

## 验证与边界

`verifyMovingAttack` 使用生产 AirCombatController、异步 mailbox/Worker、预测和激流执行器，世界、库存、矿车轨迹及伤害入口为离线夹具。五种相同初始场景从已在空中开始：静止、2 格正弦小幅运动、±10 格以 0.32 格/tick 往返、0.24 格/tick 横移、±12 格以 0.4 格/tick 改向。乘客自身 velocity 为零，位置按轨迹更新。

比较以相同 **20 ms 离线 tick 间隔**运行；实际游戏 tick 通常为 50 ms，不能将测试中的首次攻击时刻当作实机保证。异步完成时序会带来小幅差异。600 tick 无首次攻击记为未完成；最大距离统计至本轮命中后离场/安全落地或 600 tick 截止。
